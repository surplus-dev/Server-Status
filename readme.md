# Server Status

클라이언트가 3분마다 CPU, RAM, GPU 및 디스크 상태를 서버로 전송하고, 서버의 `/` 페이지에서 확인할 수 있습니다.

## 디스크 용량

- 클라이언트는 로컬 디스크와 NFS·SMB 같은 네트워크 마운트의 파일시스템별 전체 용량, 사용 용량, 남은 용량과 사용률을 수집합니다. 마운트 목록에 루트 파일시스템이 없으면 루트도 포함합니다.
- 클라이언트는 NVIDIA 실행 파일·라이브러리·설정 파일처럼 개별 파일에 연결된 마운트는 전송하지 않습니다.
- 서버는 화면을 표시할 때 `/boot`, `/efi`, `/tmp`, `/var/tmp`, `/run`, `/var/run`, `/dev`, `/proc`, `/sys` 및 그 하위 마운트를 제외합니다. `/boot/efi` 같은 부팅용 파티션과 tmpfs·ramfs 같은 임시 파일시스템, Snap 패키지의 squashfs 이미지도 제외합니다. 루트 파일시스템은 항상 포함하며, FAT 형식의 일반 데이터 디스크도 표시합니다.
- 기존 클라이언트의 컨테이너 파일 마운트도 숨기기 위해 `/etc/`, `/bin/`, `/sbin/`, `/lib/`, `/usr/bin/`, `/usr/lib/`, `/usr/share/` 등 시스템 디렉터리 아래의 로컬 하위 마운트를 서버에서 제외합니다. 해당 디렉터리 자체에 마운트된 별도 파티션과 네트워크 마운트는 이 규칙으로 제외하지 않습니다.
- Windows의 `C:`, `C:\`, `c:/`처럼 같은 드라이브를 가리키는 항목은 서버에서 중복을 제거해 한 번만 표시합니다.
- 이 표시 필터는 서버만 새로 빌드해 재시작하면 기존에 저장된 데이터에도 바로 적용됩니다. 디스크 정보를 전송하는 기존 클라이언트는 재빌드하거나 재시작할 필요가 없습니다.
- 네트워크 디스크는 마운트 경로만 표시하며 장치 이름에 포함된 원격 서버의 IP·호스트 이름과 공유 경로는 화면에 표시하지 않습니다. 주소 숨김은 서버 업데이트만으로 적용됩니다. 기존 클라이언트가 네트워크 디스크를 수집하지 못했다면 해당 클라이언트를 새로 빌드해 재시작해야 용량 정보가 전송됩니다.
- 서버 화면에는 마운트 경로와 장치 이름, 남은 용량, 전체 용량, 사용 용량 및 사용률이 표시됩니다. 용량 단위는 KiB, MiB, GiB 등 1024 기준입니다.
- 남은 용량은 클라이언트 실행 계정이 사용할 수 있는 공간입니다. 파일시스템의 예약 공간 때문에 전체 용량에서 사용 용량을 뺀 값과 다를 수 있습니다.
- 디스크를 읽지 못하면 해당 디스크는 `N/A`로 표시하고 다른 상태 정보는 계속 전송합니다. 디스크 정보가 없는 기존 클라이언트의 데이터도 `DISK: N/A`로 표시합니다.
- 서버 프로세스가 실행되는 장비도 모니터링하려면 그 장비에서 클라이언트를 실행합니다.

디스크 정보는 기존 `/api/metrics` 요청의 `disks` 배열로 전달되고 기존 메트릭과 함께 저장됩니다.

```json
{
  "disks": [
    {
      "mountpoint": "/",
      "device": "/dev/sda1",
      "fstype": "ext4",
      "total_bytes": 107374182400,
      "used_bytes": 64424509440,
      "free_bytes": 42949672960,
      "used_percent": 60
    }
  ]
}
```
